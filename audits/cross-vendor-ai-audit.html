当前实现

默认密封发牌在发牌前锁定加密牌堆。局后零知识洗牌证明核对整副加密牌，解密证明仅打开实际发出的公共牌、已亮出的牌和请求者自己的底牌。发牌方的主种子和解密密钥保持私密，对手未亮的弃牌和未发出的牌继续加密。独立发牌进程在局中持有整副牌。

高级加密房由玩家设备持有解密份额。两人局需要双方参与，三人及以上在完成准备后采用向上取整的三分之二恢复门限。当前高级加密发牌说明解释了串通假设。

默认发牌证明的源码在 pf2.rs。可在客户端核对获准查看的牌，也可按仓库说明运行 pf_verify。零知识证明介绍

Current implementation

Default sealed dealing locks an encrypted deck before the deal. The post-hand zero-knowledge shuffle proof verifies the encrypted deck. Decryption proofs open only the dealt board, shown cards and the requester’s own hole cards. The dealer’s master seed and decryption key stay private. Opponents’ unshown folded cards and undealt cards stay encrypted. The separate dealer process holds the full deck during play.

Advanced encrypted rooms keep decryption shares on player devices. Heads-up requires both players. Hands with three or more use a recovery threshold of two thirds, rounded up, after setup. The current advanced dealing guide covers the collusion assumptions.

The default proof implementation is in pf2.rs. To check permitted cards, use the in-app verifier or run pf_verify as described in the repository README. How zero-knowledge verification works

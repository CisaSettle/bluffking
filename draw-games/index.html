彩票与骰宝：开奖后台源码

这是现有 BluffKing 开源仓库的 draw-games/ 子目录。它公开实际服务端使用的抽样、中奖计算、购票封盘、兑奖和相关持久化源码；不包含数据库内容、账号数据或运行密钥。代码采用根目录的 AGPL-3.0-only 许可证，品牌规则见 商标说明。

这些游戏使用操作系统安全随机数。当前没有预先公开的种子承诺、开奖后种子揭示或可离线验证的开奖证明。公开代码让任何人检查算法与结算规则；它本身不证明某次线上开奖运行了该版本，也不提供德州盲发的密码学保证。

从开奖到兑奖

  1. 期次与时间：双色球、大乐透和 TOTO 每 5 分钟一期，大乐透错开 75 秒，TOTO 错开 150 秒；快乐8 每 2 分钟，福彩3D 每 3 分钟。开奖前 5 秒封盘，期号使用新加坡时间。
  2. 购票：校验选号和限额、锁定钱包、检查封盘与余额；重复请求回放已保存结果。请求内容哈希只用于幂等校验，不是开奖承诺。
  3. 开奖与派奖：数据库行锁协调多个后台，每期生成并保存同一组号码；逐用户事务结算，重启继续处理尚未结算的记录。
  4. 刮刮乐揭示：未刮号码在响应中为 null，但后台数据库已保存完整结果；单张最后一格揭示时兑奖，并处理过期卡片。不能据此声称服务器不知道结果。
  5. 账本、练习豆钱包与游戏记录展示结算调用和原子余额更新；当前彩票共用练习豆钱包，迁移文件中的旧彩票钱包只保留历史意义。

运行与验证边界

这是原始源码公开目录，不是独立 Rust crate，根工作区构建不编译本目录。账号生命周期锁、认证、主路由、数据库基础结构、checkpoint 解码、主机所有权、发布接管、统计与社交模块仍由主服务提供；本目录不构成完整服务器或完整主机恢复实现。

骰宝房间可能在有序持久化完成前展示已接受的结果；进程在写入前崩溃时，恢复只能依据已保存状态。源码公开不构成“所有已展示结果均已落库”的保证。

老虎机的随机中奖目前在浏览器本地运行，抓娃娃使用浏览器物理模拟，名单抽奖也在客户端；它们没有可供本目录发布的后台开奖模块。本次不把这些功能改成服务端游戏。

公开文件由上游明确文件清单逐字同步。上游发布流程对这些文件计算内容散列，并下载公开标签逐文件比对。公开标签说明对应的源码快照，不表示该快照已部署到生产。运行密钥、玩家数据与未结束的实际开奖结果均不在仓库中。

Lottery and Sicbo draw backend source

draw-games/ is a subdirectory of the existing BluffKing open-source repository. It publishes the actual server implementation for sampling, prize calculation, purchase cutoffs, redemption and related persistence. It contains no database contents, account data or runtime secrets. Code is licensed under the root AGPL-3.0-only license; see the separate trademark policy.

These games use the operating-system RNG. They currently have no published seed commitments, post-draw seed reveals or offline-verifiable draw proofs. Publishing source permits inspection of the algorithms and settlement rules; it does not prove that a particular live draw executed this version or provide poker's server-blind cryptographic guarantees.

From draw to redemption

  1. Periods and timing: SSQ, Daletou and TOTO draw every five minutes, with Daletou offset by 75 seconds and TOTO by 150 seconds; Happy8 every two minutes and Fucai3D every three. Sales close five seconds before the draw. Period labels use Singapore time.
  2. Purchases: validate entries and limits, lock the wallet, enforce the cutoff and available balance, and replay stored results for repeated requests. The request-body hash is for idempotency, not a draw commitment.
  3. Draws and awards: database row locks arbitrate concurrent backends, storing one set of numbers per period. Settlement proceeds in per-user transactions; unfinished work resumes after restart.
  4. Scratch reveals: unrevealed numbers are null in client responses, but the complete result already exists in the server database. A single card pays on its last reveal; expiry is also handled. This is not server-blind dealing.
  5. Ledger, shared practice wallet and game records expose settlement calls and atomic balance updates. Lottery now shares the beans wallet; the older lottery wallet in the migration is historical.

Runtime and verification boundaries

This is a source publication, not an independent Rust crate; the root workspace build does not compile this directory. Account-lifecycle locks, authentication, routing, base database schema, checkpoint decoding, host ownership, release handoff, statistics and social infrastructure still come from the main service. This is not a complete server or complete host-recovery implementation.

Sicbo rooms can display accepted outcomes before the ordered persistence finishes. A process crash before persistence can restore only the saved state. Publication is not a guarantee that every displayed result has already become durable.

Slots currently generates prizes locally in the browser, Claw uses browser physics, and the name picker also runs client-side. They have no backend draw modules to publish here. This change does not turn them into server games.

An explicit upstream file map copies these files byte-for-byte. The upstream publication flow hashes their contents, then downloads the public tag and compares each file. A public tag identifies a source snapshot, not proof of production deployment. Runtime secrets, player data and actual unfinished draw results are not repository contents.
